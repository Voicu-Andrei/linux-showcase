# Part 1 — Cheat Sheet

**Single terminal · ~2 minutes**

## 1. Start the target in the background

```bash
./part1/launch-target.sh &
T=$!
```

The launcher prints its PID. `$T` holds it for the rest of the demo.

## 2. List the kernel's directory for that process

```bash
ls /proc/$T/
```

> Talking point: this is **not** on disk. Every entry is generated by
> kernel code, on demand, from in-memory state.

## 3. `cmdline` — what argv was the process invoked with?

```bash
tr '\0' ' ' < /proc/$T/cmdline; echo
```

Args are NUL-separated; `tr` makes them readable.

## 4. `status` — human-readable metadata

```bash
grep -E '^(Name|State|Pid|PPid|VmRSS|Threads):' /proc/$T/status
```

- `State: S (sleeping)` — bash is blocked in `wait4()` for its `sleep` child
- `PPid` — the shell that ran `./launch-target.sh`
- `VmRSS` — resident memory in KB
- `Threads` — 1 for plain bash

## 5. `environ` — env vars at `execve()` time

```bash
tr '\0' '\n' < /proc/$T/environ | grep '^DEMO_'
```

The launcher re-execs with `env -i`, so this list is short and obviously
ours. Note: `/proc/<pid>/environ` is a **snapshot at exec time** — later
`export`s would not show up here.

## 6. `fd/` — open files as symlinks

```bash
ls -l /proc/$T/fd/
```

- `0` `1` `2` — stdin/stdout/stderr
- `3` — `/etc/hostname`
- `4` — `/etc/os-release`
- `5` — `scratch/launch-target.log`

Resolve a couple:

```bash
readlink /proc/$T/fd/3
readlink /proc/$T/fd/5
```

> Talking point: this is exactly how `lsof` works under the hood — it
> walks `/proc/*/fd/`.

## 7. Cleanup

```bash
kill $T
ls /proc/$T 2>&1 | head -1
```

The directory disappears the instant the process is reaped.
